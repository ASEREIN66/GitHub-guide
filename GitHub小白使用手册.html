GitHub 小白使用手册

从「哪个按钮在哪」到「把 vibe coding 出来的小工具变成一条永久链接」。

适用对象：第一次用 GitHub / 只想把网页小工具放上去的人 · 2026-10

先说结论：如果你只想把小工具放上去拿一个链接，全程可以在网页上点鼠标完成，不需要装 Git、不需要敲命令、不需要理解分支是什么。真正要用到的只有三个地方：+ 号建仓库、Add file 传文件、Settings 开 Pages。

0. 你找不到 "uploading an existing file"

这句话只在刚建好、还空着的仓库页面上出现，是页面中间那段提示语里的一个蓝色链接，位置不固定、新版界面还会改文案，所以不用死找。下面三条路都能到同一个上传页，第三条最稳：

方式操作说明
找链接空仓库页面中间的提示语里，蓝色文字 uploading an existing file文案可能变成别的，找不到很正常
点按钮仓库文件列表右上角 Add file → Upload files任何仓库都有，最通用
改网址浏览器地址栏直接访问：
https://github.com/你的用户名/仓库名/upload		一定有效，把用户名和仓库名换成你自己的

如果打开上传页看到的是一句「拖文件到这里」的虚线框，那就对了 —— 把文件从 Finder 拖进去即可。

1.2 个人主页（github.com/你的用户名）

这是别人点进你头像看到的页面 —— 它其实就是你的作品集首页，面试官大概率会看这里。

区域是什么你要不要管
头像 + 昵称 + bio一句话自我介绍，支持 emoji 和链接要填。写清身份和方向，比如「2027 届 · 在做 AI 内容质量与数据策略」
Pinned（置顶仓库）你手动挑出来展示的仓库，最多 6 个要设。把好项目置顶，别让仓库按时间乱排
贡献热力图绿格子，记录你每天提交了多少次不用刻意刷，但保持有更新比全灰好看
顶部标签页Overview / Repositories / Projects / Packages / Stars找仓库去 Repositories

顺手做两件事：① 在 Your repositories 里点仓库右边的星标旁边的小齿轮可以设 Pinned；② 头像旁边点 Edit profile 填 bio 和个人网站（可以把你那个工具链接填进去）。

顶部那些标签页分别是干嘛的

Settings仓库设置。开 Pages 就在这里，改名、删仓库、改可见性也在这今天就要用

1.4 文件页面

点开某个文件后，右上角有一排按钮：Raw（看纯文本原始内容）、Copy（复制全文）、Download（下载）、铅笔图标（在线编辑，改完直接提交）、垃圾桶图标（删除这个文件）。

改 README 就用铅笔。改完拉到页面最下面，填一句说明（Commit message），点 Commit changes 就存好了，不用下载再上传。

2. 名词白话解释

名词白话你要关心吗
仓库 Repository一个项目一个文件夹，只是这个文件夹住在网上、有历史记录核心概念
提交 Commit一次存档。附带一句话说明你改了什么，可以随时回到任何一次存档核心概念
分支 Branch平行时间线。默认那条叫 main，是正式版知道有 main 就够了
推送 Push / 拉取 Pull把本地存档上传 / 把网上的更新下载下来命令行方式才用
克隆 Clone把网上的仓库整个下载到本地换电脑时有用
Fork把别人的仓库复制一份到自己账号下暂时不用
Star收藏 + 点赞。别人点星代表认可你的仓库被点星是简历素材
Issue一个问题 / 一条待办可以当自己的需求清单
Release打包发布一个版本工具成熟后可以做
PagesGitHub 免费提供的静态网页托管 —— 把仓库变成一个能打开的网址本次目标
README.md仓库说明书，用 Markdown 写，自动显示在首页必写
.gitignore黑名单，列出不上传的文件（如系统垃圾文件、密钥）有则更好
LICENSE开源协议。没有的话默认是「保留所有权利」，别人不能随便用想被人用就加 MIT

3. 上传你的小工具：完整流程

下面以你的论文格式校验工具为例，仓库名统一用 thesis-format-checker，需要上传的文件在：

~/Desktop/github-pages/
├── index.html    78 KB，工具本体
├── README.md     说明书，已写好
└── .gitignore

3.0 先决定走哪条路

方式适合要装东西吗以后更新
网页法第一次上传、只想快点拿到链接什么都不用装每次手动删旧文件再传新的，稍麻烦
命令行法会频繁改、想把仓库当正式项目维护本机已有 Git，再生成一个 token一条命令搞定

建议：今天先用网页法把链接拿到手（10 分钟）。等你确认要长期维护了，再补命令行方式。

3.1 网页法（推荐，今天就用这个）

1
注册 / 登录

打开 github.com → 右上角 Sign up。邮箱建议用常用邮箱，注册完会让你验证。

用户名要想清楚。它会永久出现在链接里：https://用户名.github.io/仓库名/。这个链接要进简历，建议用真名拼音，不要用 coolboy2026 这种。以后可以改名，但改名会让旧链接失效。

2
新建仓库

右上角 + → New repository，按下面填：

字段填什么
Repository namethesis-format-checker（只能用小写字母、数字、短横线，不能有空格）
Description一句话，比如「毕业论文格式校验工具，纯前端零依赖」
Public / Private选 Public。免费账号只有公开仓库能免费用 Pages
Add a README file不勾（我们已有 README）
Add .gitignore不勾（我们已有）
Choose a license可先不勾；想加就选 MIT

点 Create repository。

3
上传文件
方法：地址栏直接访问 https://github.com/你的用户名/thesis-format-checker/upload
  1. 把 github-pages 文件夹里的 index.html 和 README.md 拖进页面的虚线框（.gitignore 可选）。
  2. 下面的 Commit message 填一句说明，比如 发布毕业论文格式校验工具。
  3. 确认选的是 Commit directly to the main branch。
  4. 点绿色 Commit changes。

看不到 .gitignore？它是隐藏文件。在访达里按 Shift + Command + . 就能显示隐藏文件。传漏了也不影响工具运行，可以不管。

网页上传的限制：单个文件别超过 25 MB（你的 index.html 只有 78 KB，远低于限制），一次别超过 100 个文件。

4
开启 GitHub Pages
Settings → 左侧 Pages → Build and deployment
  • Source：选 Deploy from a branch
  • Branch：左边选 main，右边选 / (root)
  • 点 Save

注意：Settings 在仓库页面最上面一排标签的最右边，不是右上角的头像菜单里的 Settings（那是账号设置）。

5
等 1–3 分钟，访问链接
https://你的用户名.github.io/thesis-format-checker/
  • 首次生效期间会显示 404，这是正常的，等一两分钟再刷新。
  • 想看部署进度：仓库顶部 Actions 标签里，有个叫 pages build and deployment 的任务，黄色圆点=正在跑，绿色对勾=成功。
  • Pages 设置页顶部出现 Your site is live at ... 就说明好了。
6
回填 README 里的真实地址

回到 Code 页 → 点 README.md → 右上角铅笔 → 把第 5 行那句占位链接换成真实地址 → 拉到底点 Commit changes。

到这里就结束了。你已经有一个永久链接、一个公开仓库、一份展示用的 README。

3.2 命令行法（以后频繁更新时用）

第一步：生成 token（一次性）

GitHub 早已不支持用密码推送，必须用 token 当密码。

  1. 右上角头像 → Settings（这个是账号设置）
  2. 左侧最下面 Developer settings → Personal access tokens → Tokens (classic)
  3. Generate new token (classic) → 备注随便填 → 勾选 repo → 拉到底 Generate token
  4. 复制那串 ghp_ 开头的字符，只显示这一次，关掉页面就没了

第二步：在本机跑这几条命令

# 0) 先登记身份（只需做一次，你的机器目前还没配置）
git config --global user.name "你的GitHub用户名"
git config --global user.email "你注册GitHub用的邮箱"

# 1) 进入工具目录
cd ~/Desktop/github-pages

# 2) 初始化仓库，把当前分支命名为 main
git init -b main

# 3) 先看看要提交哪些东西（确认没有密钥、大文件混进去）
git status

# 4) 全部加入暂存，然后提交
git add .
git commit -m "feat: 发布毕业论文格式校验工具"

# 5) 关联远程仓库（把用户名和仓库名换成你自己的）
git remote add origin https://github.com/你的用户名/thesis-format-checker.git

# 6) 推送
git push -u origin main

推送时提示输入密码 → 粘贴那个 token（不是你的 GitHub 登录密码）。终端里粘贴密码不会显示星号，直接回车就行。

第 5 步的前提：GitHub 上那个仓库必须是空的（建仓库时别勾 README）。如果远程已经有文件，push 会被拒绝，见第 5 节报错表。

4. 以后怎么更新工具

场景网页法命令行法
改了工具本体进仓库点 index.html → 右上角垃圾桶 Delete → 再 Add file → Upload files 传新版（文件名必须仍叫 index.html）把新文件覆盖到 github-pages/index.html，然后 git add . && git commit -m "fix: 修正标题字号误报" && git push
改 README 文字铅笔图标在线改，最方便本地改完 push
加新文件Add file → Upload files同上

改完 Pages 不用重新设置，1–2 分钟后自动生效。刷新时如果没变化，按 Command + Shift + R 强制刷新（浏览器缓存）。

5. 报错对照表

错误提示原因怎么修
failed to push some refs远程有本地没有的文件（通常是建仓库时勾了 README）先 git pull --rebase origin main 再 push；或者删掉远程仓库重建一个空的
Authentication failed / Support for password authentication was removed用了登录密码，或 token 过期 / 权限不够重新生成 token，勾选 repo，粘贴时别带空格
fatal: not a git repository当前目录没初始化先 git init，或 cd 到正确目录
refusing to merge unrelated histories本地和远程是两个不相干的仓库git pull origin main --allow-unrelated-histories
Pages 链接 404还没部署完 / 分支选错 / 主文件不叫 index.html等 2 分钟；检查 Settings → Pages 里分支是 main、目录是 / (root)；确认首页文件叫 index.html
页面打开了但样式全乱相对路径不对，或 CSS/JS 没传上去检查文件是否都传了，且 index.html 在仓库根目录
仓库名已存在这个用户名下已有同名仓库换个名字，或先删掉旧的
上传时提示文件过大单文件超过 25 MB（硬上限 100 MB）压缩资源；视频/大文件不要放仓库，用别的方式托管

6. 拿到链接之后

两条链接怎么用

链接特点
github.io跟你个人账号绑定，不删仓库就一直在；面试官看得到源码
WorkBuddy 链接国内直连、打开快，但挂在工作台账号下

作品集里两个都放：GitHub 那个当主链接（显得专业、能看源码），WorkBuddy 那个当国内备用。

顺手补的三件小事

  1. 加话题标签：仓库 About 右边的齿轮 → 填 docx、thesis、frontend、format-checker，别人能搜到
  2. 把仓库置顶：个人主页 → Pinned → Edit pinned items
  3. 发一个 Release：仓库右侧 Releases → Create a new release，标签填 v1.0，把 index.html 附上，别人可以直接下载离线版

对求职的意义：一个能打开的工具链接 + 一份讲清「解决什么问题、怎么设计、怎么实现」的 README，比简历上写「熟悉前端」有说服力得多。README 里那几段设计要点（规则项与参数分离、抽取+人工确认闭环）记得保留，那是面试能聊的东西。

本手册针对「把本地网页小工具发布到 GitHub Pages」这一件事写成，其余功能（分支协作、CI、Actions）暂不涉及，用到时再学。
